## 開始前

- 確認你已登入正確的 HQ 工作區。
- 確認已選擇正確品牌。
- 確認需要調查的是哪間店舖或哪部終端。
- 此頁用於營運疑難排解。除非內部流程允許，否則不要下載或分享日誌。

## 開啟此頁

1. 在 Analytics 區域開啟 `日誌`。
2. 選擇 `API 日誌` 查看第三方通訊，或 `POS 日誌` 查看終端檔案。

## 此頁用途

`日誌` 是 HQ 內日誌相關工具的總覽頁。

- `HQ 稽核軌跡`：即將推出。日後用於查看管理設定與使用者操作歷史。
- `API 日誌`：按品牌或分店查看現有的第三方請求、回應及錯誤。
- `POS 日誌`：現已可用。用於查看 POS 終端上載的日誌檔案。

`POS 日誌` 不會更改 POS 行為。它只協助你查看已由 POS 上載的檔案。

## 查看第三方 API 日誌

1. 開啟 `日誌` → `API 日誌`。
2. 在 `品牌／分店` 選擇所需範圍。
3. 選擇 `日誌類型`。查看 Keeta 菜單同步時，選擇 `Keeta / MeiTuan`。
4. 輸入 `開始日期 (UTC)` 及 `結束日期 (UTC)`。
5. 按 `套用`。
6. 按請求旁的 `查看`，開啟 `日誌詳情`。
7. 展開 `回應內容` 及請求區段，檢查結果。

日期包括開始及結束日，最多可選 7 日。請先將問題發生時間轉換為 UTC。最新請求顯示在最前；使用頁面控制查看更多結果。按 `重新整理` 會重新載入已套用的篩選範圍。

`僅品牌日誌` 不包括分店日誌。請選擇指定分店以查看其通訊記錄。只有分店權限的使用者只能查看已獲分配的分店，不能查看品牌日誌。

`日誌詳情` 包括 HTTP 狀態、時間、方法、網域、來源、請求查詢參數、標頭及內容。憑證已隱藏，但日誌可能仍含其他個人或業務資料，分享前請仔細檢查。每個欄位最多預覽 32,768 個字元，超出時會顯示提示。

HTTP 成功不代表第三方已完成操作。請閱讀回應，並在第三方系統核實結果。沒有日誌時，請確認分店、類型及 UTC 日期。資料過多或服務逾時時，請縮短日期範圍。來源無法使用時，請聯絡管理員；錯誤不代表沒有記錄。

若 `同步菜單` 提示 Keeta 設定未啟用，請與管理員檢查 MeiTuan 設定中的 `啟用 Webhook` 及 `啟用菜單同步`。儲存所需設定後再重試。查看 API 日誌不會啟用整合或重試操作。

## 主要區段

![POS 日誌頁面](/img/hq/logs/pos_logs_page.png)

### 崩潰報告

`崩潰報告` 用於查看 POS 自動上載的崩潰檔案。這些檔案通常協助支援人員了解 App 為何異常停止。

### 應用程式日誌

`應用程式日誌` 用於查看使用者從 POS 手動上載的執行記錄。

### Octopus 日誌

排查 POS Octopus 付款活動時，使用 `Octopus 日誌`。

### 其他上載日誌

`其他上載日誌` 用於查看不屬於其他區段的手動上載診斷檔案。

## 主要操作

### 按店舖篩選

1. 開啟 `POS 日誌`。
2. 使用右上方的店舖篩選器。
3. 選擇 `所有店舖` 查看所有已對應店舖，或選擇單一店舖縮窄範圍。

每個表格每頁最多顯示 500 行。如有更多檔案，使用表格底部的頁面控制。

### 在日誌區段內搜尋

1. 找到需要的區段，例如 `崩潰報告` 或 `應用程式日誌`。
2. 使用該區段的搜尋欄。
3. 可用檔案名稱、店舖、平台、App 版本或日期文字搜尋。

### 快速檢視日誌

1. 找到日誌檔案。
2. 選擇 `快速檢視`。
3. 查看預覽內容。
4. 如需完整內容，請下載檔案。

大型檔案的預覽可能只顯示檔案開首內容。

### 下載日誌

1. 找到日誌檔案。
2. 選擇 `下載`。
3. 按內部支援流程儲存或分享檔案。

## 儲存後的影響

此頁沒有儲存操作。查看、篩選、預覽與下載日誌都不會更改 POS 設定或店舖資料。

## 如何檢查結果

- 確認所選品牌與店舖篩選器正確。
- 確認檔案名稱、`店舖`、`發生時間` 與 `上載時間` 與調查事項相符。
- 對於崩潰報告，升級處理前先檢查 `平台` 和 `App 版本`。

## 如果出現問題

- 如頁面顯示 `找不到日誌`，確認已選擇正確品牌與店舖。
- 如找不到店舖，確認該店舖已有 POS 店舖對應。
- 如找不到檔案，請 POS 使用者再次從 POS 終端上載日誌。
- 如 `快速檢視` 顯示內容不足，使用 `下載`。

## 何時要找店主／管理員

- 你沒有需要品牌或店舖的存取權。
- 日誌可能包含顧客或員工敏感資料。
- 你需要將檔案傳送到組織外部。
- 你正在調查重複崩潰、付款失敗或安全相關活動。
